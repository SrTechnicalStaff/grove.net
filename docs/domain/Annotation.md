# Annotation

## Definition

An Annotation is a derived reading surface that assembles Content and Memory
context from a local Field Ledger region. It is a view of relationships already
present in the Grid; it is not a new Memory, Content, Anchor, or Placement.

## Formation

An Annotation is requested from a saturated or otherwise qualified field. The
system selects relevant Content across Grid Layers, resolves their Memory
records, and lays out a readable synthesis. The Annotation may expose native
Grid-Layer and Content context so a person can return to a source.

## Mutation rules

Reading an Annotation does not create or edit records. A command from an
Annotation may route to Memory Search, Writing Slate, Gallery Slate, or a Grid
Content destination. The destination operation owns any resulting mutation.

An Annotation does not own the Content it presents and must not snapshot a
second semantic copy merely to render a page.

## Boundary decisions

| Tension | Decision |
| --- | --- |
| Annotation vs Memory | Annotation presents Memory context; it is not a Memory. |
| Annotation vs Content | Annotation derives from Content; Content remains the source. |
| Annotation vs Aura | Aura/Field Ledger evidence may qualify the source region. |
| Annotation vs Slate | Annotation is a derived reading surface; a Slate is a named sub-application. |
| Annotation vs Overlay | The interaction chrome may be an Overlay, but the Annotation meaning is derived content. |
