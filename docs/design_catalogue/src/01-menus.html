01Surface fill, 2px radiusFill #161618 on a quiet 1px border. 2px is the only radius Grove chrome owns; a rounded menu is a foreign object.
02No scrimThe Grid context behind stays fully lit and live. Nothing dims to make a menu matter — it is chrome, not an event.
03Label left, key rightA plain verb in UI type, one unmodified stroke in mono at reduced ink. Rows never wrap and never truncate.
04Hairline groupsA 1px separator bounds each intent group: open and edit, clipboard, context, removal. Grouping is the only hierarchy a menu gets.
05Destructive stands aloneRemove reads in the invalid role, in its own group, never beside the default row — a fast hand cannot land on it by habit.
06No titleA menu names nothing, not even itself. The thing that was clicked is the title.

01One grammar, three targetsContent, empty space, and the inside of a surface all get the same cloth: same fill, same rows, same keys. Only the actions change.
02A short list per targetEach target answers with the actions it supports and no others — open, edit, clipboard, duplicate, remove where they apply, plus what only that target can do.
03Omitted, never grayedAn action that does not apply is absent. A disabled gray row is an apology for a wrong list; Grove does not print apologies.
04No actions, no menuA target with nothing to offer shows nothing at all. An empty menu — or a menu of one filler row — never opens.

01The surface answersEvery surface supplies its own short list of what it can do. There is no single global menu carrying rows that do not apply here.
02Borrowed vocabularyA text editor answers like a plain text editor; a viewer answers like a photo viewer. The words people already own are the right words.
03Two rows is a whole menuA short list is a correct list. Length is never padded to look substantial, and a row never appears just to fill a group.
04Same cloth, different wordsFill, border, radius, label left and key right do not change from one surface to the next. Only the actions do.
05Opening changes nothingThe menu asks the surface what it offers and draws it. No draft is saved, no view moves, no state is touched until a row is chosen.

01Parent row heldMove to stays highlighted the whole time its flyout is open. The eye can always trace the child back to the row that owns it.
02Flipped at the edgeNear the right edge the flyout opens leftward, and the row's arrow points the way. The whole menu is always on screen — never clipped, never scrolled.
03Digits pick destinationsDestinations are numbered 1–n in mono. One keystroke moves the content; the digit is the quick key, so no row carries a second one.
04One level, everA flyout never opens a flyout. A list too deep for one level is navigation, and navigation is not a menu's job.
05Left-arrow retreats one step← closes only the flyout and returns to the held row. Escape still closes the topmost surface — here, that same flyout first.

01Single strokes, printedEvery row shows its key — one unmodified stroke, no chords to memorize. T fires Trace the instant it is pressed.
02Live only while openQuick keys belong to the menu, not the Grid. Closed, T types a letter again; nothing is globally reserved.
03Hover and arrows agree↑↓ walk the rows, Enter fires the lit one. Pointer and keyboard light the identical row state — one highlight, two hands.
04Escape peels one layerEscape closes the topmost surface and only that surface — flyout before menu, menu before nothing.
05Stable orderWithin a target kind the rows never reshuffle — the HIG rule that muscle memory is part of the contract. Position is learned once.
